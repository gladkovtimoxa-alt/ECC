# Команда Aside

Задайте вопрос посреди задачи и получите немедленный, сфокусированный ответ — затем продолжите точно с того места, где остановились. Текущая задача, файлы и контекст никогда не изменяются.

## Когда использовать

- Вам любопытно что-то, пока Claude работает, и вы не хотите терять темп
- Вам нужно короткое объяснение кода, который Claude сейчас редактирует
- Вы хотите второе мнение или уточнение по решению без увода задачи в сторону
- Вам нужно понять ошибку, концепцию или паттерн, прежде чем Claude продолжит
- Вы хотите спросить что-то не связанное с текущей задачей без начала новой сессии

## Использование

```
/aside <ваш вопрос>
/aside что на самом деле возвращает эта функция?
/aside этот паттерн потокобезопасен?
/aside почему мы используем X вместо Y здесь?
/aside какая разница между foo() и bar()?
/aside стоит ли беспокоиться о запросе N+1, который мы только что добавили?
```

## Процесс

### Шаг 1: заморозить текущее состояние задачи

Перед тем как отвечать на что-либо, мысленно отметьте:
- Какая активная задача? (над каким файлом, функцией или проблемой шла работа)
- Какой шаг выполнялся в момент вызова `/aside`?
- Что должно было произойти далее?

НЕ трогайте, не редактируйте, не создавайте и не удаляйте файлы во время aside.

### Шаг 2: ответить на вопрос напрямую

Отвечайте на вопрос в самой краткой форме, которая всё ещё полная и полезная.

- Начинайте с ответа, а не с рассуждения
- Держите кратко — если нужно полное объяснение, предложите углубиться после задачи
- Если вопрос про текущий файл или код, над которым идёт работа, ссылайтесь на него точно (путь к файлу и номер строки, если релевантно)
- Если для ответа нужно прочитать файл, прочитайте его — но только читайте, никогда не пишите

Отформатируйте ответ так:

```
ASIDE: [кратко переформулируйте вопрос]

[Ваш ответ здесь]

— Назад к задаче: [однострочное описание того, что делалось]
```

### Шаг 3: возобновить основную задачу

После ответа немедленно продолжите активную задачу с точного места, где она была приостановлена. Не спрашивайте разрешения на возобновление, если только ответ aside не раскрыл блокер или причину пересмотреть текущий подход (см. Граничные случаи).

---

## Граничные случаи

**Вопрос не предоставлен (`/aside` без ничего после):**
Ответьте:
```
ASIDE: вопрос не предоставлен

Что бы вы хотели узнать? (задайте ваш вопрос, и я отвечу без потери контекста текущей задачи)

— Назад к задаче: [однострочное описание того, что делалось]
```

**Вопрос раскрывает потенциальную проблему с текущей задачей:**
Отметьте это явно перед возобновлением:
```
ASIDE: [ответ]

ПРЕДУПРЕЖДЕНИЕ: Примечание: этот ответ предполагает [проблему] с текущим подходом. Хотите решить это перед продолжением, или продолжить как планировалось?
```
Дождитесь решения пользователя перед возобновлением.

**Вопрос на самом деле — смена направления задачи (не побочный вопрос):**
Если вопрос подразумевает изменение того, что строится (например, `/aside кстати, давай используем Redis вместо этого`), уточните:
```
ASIDE: Это похоже на смену направления, а не просто побочный вопрос.
Вы хотите:
  (a) Ответить на это только информационно и сохранить текущий план
  (b) Приостановить текущую задачу и изменить подход
```
Дождитесь ответа пользователя — не делайте предположений.

**Вопрос про текущий открытый файл или код:**
Отвечайте из живого контекста. Если файл был прочитан ранее в сессии, ссылайтесь на него напрямую. Если нет, прочитайте его сейчас (только чтение) и ответьте со ссылкой file:line.

**Нет активной задачи (ничего не выполняется в момент вызова `/aside`):**
Всё равно используйте стандартную обёртку, чтобы форма ответа оставалась консистентной:
```
ASIDE: [кратко переформулируйте вопрос]

[Ваш ответ здесь]

— Назад к задаче: нет активной задачи для возобновления
```

**Вопрос требует длинного ответа:**
Дайте суть ответа кратко, затем предложите:
```
Это краткая версия. Хотите более глубокое объяснение после того, как мы закончим [текущую задачу]?
```

**Несколько вопросов `/aside` подряд:**
Отвечайте на каждый по порядку. После последнего ответа возобновите основную задачу. Не теряйте состояние задачи через цепочку aside.

**Ответ aside подразумевает необходимость изменения кода:**
Отметьте необходимое изменение, но не делайте его во время aside:
```
ASIDE: [ответ]

 Стоит исправить: [что следует изменить]. Я отмечу это после текущей задачи, если вы не хотите решить это сейчас.
```

**Вопрос неоднозначен или слишком расплывчат:**
Задайте один уточняющий вопрос — самый короткий вопрос, который даёт информацию, необходимую для ответа. Не задавайте несколько вопросов.

## Пример вывода

```
User: /aside что на самом деле делает fetchWithRetry()?

ASIDE: что делает fetchWithRetry()?

fetchWithRetry() (src/api/retry.ts:12) пытается выполнить запрос до 3 раз с
экспоненциальной задержкой (250мс → 500мс → 1с). Повторяет только на ответах 5xx и
сетевых ошибках — ошибки 4xx считаются финальными и не повторяются.

— Назад к задаче: рефакторинг auth middleware в src/middleware/auth.ts
```

```
User: /aside наш подход потокобезопасен?

ASIDE: текущий подход потокобезопасен?

Нет — общий объект кеша в src/cache/store.ts:34 мутируется без блокировки.
При конкурентных запросах это состояние гонки. Низкий риск в однопроцессном
Node.js-сервере, но стало бы реальной проблемой с worker threads или кластеризацией.

ПРЕДУПРЕЖДЕНИЕ: Примечание: это может повлиять на функцию, которую мы строим. Решить это сейчас или продолжить и исправить в follow-up?
```

---

## Примечания

- Никогда не изменяйте файлы во время aside — только доступ для чтения
- Aside — это пауза в разговоре, не новая задача — исходная задача всегда должна возобновляться
- Держите ответы сфокусированными: цель — быстро разблокировать пользователя, не читать лекцию
- Если aside вызывает более крупную дискуссию, сначала закончите текущую задачу, если только aside не раскрывает блокер
- Aside не сохраняются в файлы сессии, если они явно не релевантны результату задачи
