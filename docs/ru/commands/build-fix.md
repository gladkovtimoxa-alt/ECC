# Build and Fix

Инкрементально исправлять ошибки сборки и типов минимальными, безопасными изменениями.

## Шаг 1: определить систему сборки

Определите инструмент сборки проекта и запустите сборку:

| Индикатор | Команда сборки |
|-----------|---------------|
| `package.json` со скриптом `build` | `npm run build` или `pnpm build` |
| `tsconfig.json` (только TypeScript) | `npx tsc --noEmit` |
| `Cargo.toml` | `cargo build 2>&1` |
| `pom.xml` | `mvn compile` |
| `build.gradle` | `./gradlew compileJava` |
| `go.mod` | `go build ./...` |
| `pyproject.toml` | `python -m compileall -q .` или `mypy .` |

## Шаг 2: разобрать и сгруппировать ошибки

1. Запустите команду сборки и захватите stderr
2. Сгруппируйте ошибки по пути файла
3. Отсортируйте по порядку зависимостей (сначала исправляйте импорты/типы, затем ошибки логики)
4. Посчитайте общее количество ошибок для отслеживания прогресса

## Шаг 3: цикл исправления (по одной ошибке за раз)

Для каждой ошибки:

1. **Прочитать файл** — используйте инструмент Read, чтобы увидеть контекст ошибки (10 строк вокруг ошибки)
2. **Диагностировать** — определить корневую причину (отсутствующий импорт, неверный тип, синтаксическая ошибка)
3. **Минимально исправить** — используйте инструмент Edit для наименьшего изменения, решающего ошибку
4. **Перезапустить сборку** — проверить, что ошибка исчезла и не введены новые ошибки
5. **Перейти к следующей** — продолжить с оставшимися ошибками

## Шаг 4: guardrails

Остановитесь и спросите пользователя, если:
- Исправление вводит **больше ошибок, чем решает**
- **Та же ошибка сохраняется после 3 попыток** (вероятно более глубокая проблема)
- Исправление требует **архитектурных изменений** (не просто исправление сборки)
- Ошибки сборки возникают из-за **отсутствующих зависимостей** (нужен `npm install`, `cargo add` и т.д.)

## Шаг 5: резюме

Покажите результаты:
- Исправленные ошибки (с путями к файлам)
- Оставшиеся ошибки (если есть)
- Новые введённые ошибки (должно быть ноль)
- Предложенные следующие шаги для нерешённых проблем

## Стратегии восстановления

| Ситуация | Действие |
|-----------|--------|
| Отсутствующий модуль/импорт | Проверить, установлен ли пакет; предложить команду установки |
| Несовпадение типов | Прочитать оба определения типа; исправить более узкий тип |
| Циклическая зависимость | Выявить цикл через граф импортов; предложить выделение |
| Конфликт версий | Проверить `package.json` / `Cargo.toml` на ограничения версий |
| Неправильная конфигурация инструмента сборки | Прочитать конфиг-файл; сравнить с рабочими умолчаниями |

Исправляйте по одной ошибке за раз для безопасности. Предпочитайте минимальные диффы рефакторингу.
