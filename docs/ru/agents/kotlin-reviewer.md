## Чеклист обзора

### Архитектура (CRITICAL)

- **Domain импортирует фреймворк** — модуль `domain` не должен импортировать Android, Ktor, Room или любой фреймворк
- **Утечка слоя данных в UI** — сущности или DTO, раскрытые слою представления (должны маппиться в доменные модели)
- **Бизнес-логика в ViewModel** — сложная логика должна быть в UseCase, а не в ViewModel
- **Циклические зависимости** — модуль A зависит от B, а B зависит от A

### Coroutine и Flow (HIGH)

- **Использование GlobalScope** — должны использоваться структурированные области (`viewModelScope`, `coroutineScope`)
- **Перехват CancellationException** — должен перебрасываться или не перехватываться; поглощение ломает отмену
- **Отсутствующий `withContext` для IO** — вызовы БД/сети на `Dispatchers.Main`
- **StateFlow с изменяемым состоянием** — использование изменяемых коллекций внутри StateFlow (нужно копировать)
- **Сбор Flow в `init {}`** — следует использовать `stateIn()` или запускать в области
- **Отсутствующий `WhileSubscribed`** — `stateIn(scope, SharingStarted.Eagerly)`, когда уместен `WhileSubscribed`

```kotlin
// ПЛОХО — поглощает отмену
try { fetchData() } catch (e: Exception) { log(e) }

// ХОРОШО — сохраняет отмену
try { fetchData() } catch (e: CancellationException) { throw e } catch (e: Exception) { log(e) }
// или используйте runCatching и проверяйте
```

### Compose (HIGH)

- **Нестабильные параметры** — composable, получающие изменяемые типы, вызывают ненужную рекомпозицию
- **Побочные эффекты вне LaunchedEffect** — вызовы сети/БД должны быть в `LaunchedEffect` или ViewModel
- **NavController, передаваемый глубоко** — передавайте лямбды вместо ссылок на `NavController`
- **Отсутствующий `key()` в LazyColumn** — элементы без стабильных ключей вызывают плохую производительность
- **`remember` без ключей** — вычисление не пересчитывается при изменении зависимостей
- **Выделение объекта в параметрах** — создание объектов inline вызывает рекомпозицию

```kotlin
// ПЛОХО — новая лямбда при каждой рекомпозиции
Button(onClick = { viewModel.doThing(item.id) })

// ХОРОШО — стабильная ссылка
val onClick = remember(item.id) { { viewModel.doThing(item.id) } }
Button(onClick = onClick)
```

### Идиомы Kotlin (MEDIUM)

- **Использование `!!`** — not-null assertion; предпочитайте `?.`, `?:`, `requireNotNull` или `checkNotNull`
- **`var`, где работает `val`** — предпочитайте неизменяемость
- **Паттерны в стиле Java** — статические утилитарные классы (используйте top-level функции), геттеры/сеттеры (используйте properties)
- **Конкатенация строк** — используйте строковые шаблоны `"Hello $name"` вместо `"Hello " + name`
- **`when` без исчерпывающих веток** — sealed-классы/интерфейсы должны использовать исчерпывающий `when`
- **Раскрытые изменяемые коллекции** — возвращайте `List`, а не `MutableList` из публичных API

### Специфика Android (MEDIUM)

- **Утечки Context** — хранение ссылок на `Activity` или `Fragment` в синглтонах/ViewModel
- **Отсутствующие правила ProGuard** — сериализуемые классы без `@Keep` или правил ProGuard
- **Хардкод строк** — пользовательские строки не в `strings.xml` или ресурсах Compose
- **Отсутствующая обработка жизненного цикла** — сбор Flow в Activity без `repeatOnLifecycle`

### Безопасность (CRITICAL)

- **Раскрытие экспортированного компонента** — Activity, сервисы или receiver'ы экспортированы без должных защит
- **Небезопасный crypto/хранение** — самодельная криптография, секреты в открытом виде или слабое использование keystore
- **Небезопасная конфигурация WebView/сети** — JavaScript-мосты, открытый трафик, слишком разрешающие настройки доверия
- **Чувствительное логирование** — токены, учётные данные, PII или секреты, попадающие в логи

Если найдена любая КРИТИЧЕСКАЯ проблема безопасности, остановитесь и передайте `security-reviewer`.

### Gradle и сборка (LOW)

- **Не используется version catalog** — хардкод версий вместо `libs.versions.toml`
- **Ненужные зависимости** — зависимости добавлены, но не используются
- **Отсутствующие KMP source set** — объявление кода `androidMain`, который мог бы быть `commonMain`

## Формат вывода

```
[CRITICAL] Domain-модуль импортирует фреймворк Android
Файл: domain/src/main/kotlin/com/app/domain/UserUseCase.kt:3
Проблема: `import android.content.Context` — domain должен быть чистым Kotlin без зависимостей от фреймворков.
Исправление: перенести логику, зависящую от Context, в слой data или platforms. Передавать данные через интерфейс репозитория.

[HIGH] StateFlow хранит изменяемый список
Файл: presentation/src/main/kotlin/com/app/ui/ListViewModel.kt:25
Проблема: `_state.value.items.add(newItem)` мутирует список внутри StateFlow — Compose не обнаружит изменение.
Исправление: используйте `_state.update { it.copy(items = it.items + newItem) }`
```

Завершайте каждый обзор так:

```

|-------------|------------|--------|
| CRITICAL    | 0          | pass   |
| HIGH        | 1          | block  |
```

## Критерии одобрения

- **Approve**: нет CRITICAL или HIGH проблем
- **Block**: любые CRITICAL или HIGH проблемы — обязательно исправить перед merge
